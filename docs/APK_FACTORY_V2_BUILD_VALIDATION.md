## 1. Validation methodology

Build validation was performed in two layers:

1. **Unit / integration tests** — 73 tests run with `npm test` in `worker/`. These cover sandbox arg construction, shell-mode runtime, framework detection, engine command composition, artifact upload, workspace cleanup, log redaction, and scanner logic.
2. **Phase 4 fixture runner** — 4 synthetic project fixtures exercised stages 2 (DETECT) and 3 (VALIDATE) end-to-end without a Docker daemon. Stage 5 (BUILD) requires a daemon and is not exercisable in the CI-less validation environment.

> **Note on real compilation**: No real Gradle/APK build was attempted because no Docker daemon is available in the current remote execution environment. The fixture runner validates the full detection-and-validation path; the BUILD stage is architecture-validated through unit tests that mock the sandbox command construction.

## 3. Engine architecture (stages not requiring Docker)

### 3.1 ANDROID_NATIVE engine

- `shell: false` — command is passed directly to `docker run` as argv.
- `gradleCommand` from `stageValidate`: `./gradlew assembleDebug` (DEBUG), `./gradlew assembleRelease` (RELEASE), `./gradlew bundleRelease` (AAB).
- Working directory: project root (gradlew at root).

### 3.2 REACT_NATIVE_CLI engine

- `shell: true` — command is a bash one-liner: `set -euo pipefail && pnpm install --frozen-lockfile && cd android && chmod +x ./gradlew && ./gradlew assembleDebug --no-daemon …`
- `SKIP_GRADLE_PRECHECK=true` env var injected by `BaseDockerRuntime` to prevent the multi-step engine from running gradlew twice.
- Package manager install command: `npm ci` / `yarn --frozen-lockfile` / `pnpm install --frozen-lockfile`.

### 3.3 EXPO engine

- `shell: true` — same structure as RN CLI, plus conditional `npx expo prebuild --platform android --no-install` only when `ctx.buildSystemInfo?.androidGenerated !== true`.
- Prebuild is skipped when `android/` is already committed in the project (`androidGenerated = true`).

## 5. Compilation attempt

A real APK compilation (stage 5) was not attempted because:

1. No Docker daemon is present in the remote execution environment.
2. Network access to `repo.reactnative.dev` (React Native AARs) has not been validated live from inside a sandbox container.
3. The NDK download from the Dockerfile `sdkmanager` step requires an `apt`/network-reachable Google download host at image-build time.

The mission constraint "Ne pas annoncer GO compilation tant qu'aucun APK n'est effectivement produit et vérifié" is respected. No GO compilation is announced.

**Preconditions for a successful real APK build**:

| Precondition | Status |
|---|---|
| Docker daemon available | Required — not present in this environment |
| `docker build docker/android-builder` succeeds | Cannot verify without daemon |
| `repo.reactnative.dev` reachable from build container | Allow-list entry added; proxy config must route through squid |
| NDK 27.1.12297006 installed in image | Added to Dockerfile; requires `docker build` to verify |
| Gradle wrapper download from `services.gradle.org` | Allow-list entry present |
